# Forum service

Standalone Java 17 / Spring Boot REST service. Uses Oracle for categories, topics and comments; it does not own or modify user records. Configuration: `ORACLE_JDBC_URL`, `ORACLE_USERNAME`, `ORACLE_PASSWORD`, `USERS_SERVICE_URL` (defaults to `http://users-service:8081`), and `DDL_AUTO` (defaults to `validate`). Build/run: `mvn test`, `mvn spring-boot:run`, or `docker build -t forum-service:local .`. Parent integration owns Oracle SQL and Compose.

Every request supplies `Authorization: Bearer <token>`. The service forwards the unchanged token to `GET ${USERS_SERVICE_URL}/api/auth/me` and accepts only HTTP 200 with numeric `id` and exact role `USER` or `ADMIN`. Any request failure/non-200/invalid identity is 401. Identity and role are never accepted from body parameters. USER and ADMIN may create topics/comments. Only topic/comment author or ADMIN may update/delete them; only ADMIN may create/update/delete categories. All authenticated roles can read categories, topics and comments. Routes are `/api/categories` CRUD, `/api/topics` CRUD, `GET /api/topics?search=...`, and `/api/topics/{id}/comments` GET/POST plus `/{commentId}` PUT/DELETE.

## Oracle contract and seed guidance

The service uses the configured Oracle account's own schema. Apply equivalent reviewed DDL before launch with `DDL_AUTO=validate`; no schema or user management is performed here. Names/types must match JPA mappings: `FORUM_CATEGORY(ID NUMBER(19) GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY, NAME VARCHAR2(100) NOT NULL UNIQUE)`; `FORUM_TOPIC(ID NUMBER(19) GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY, TITLE VARCHAR2(200) NOT NULL, BODY VARCHAR2(4000) NOT NULL, AUTHOR_ID NUMBER(19) NOT NULL, CATEGORY_ID NUMBER(19) NOT NULL REFERENCES FORUM_CATEGORY(ID), CREATED_AT TIMESTAMP WITH TIME ZONE NOT NULL)`; `FORUM_COMMENT(ID NUMBER(19) GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY, TOPIC_ID NUMBER(19) NOT NULL REFERENCES FORUM_TOPIC(ID), AUTHOR_ID NUMBER(19) NOT NULL, BODY VARCHAR2(2000) NOT NULL, CREATED_AT TIMESTAMP WITH TIME ZONE NOT NULL)`. User IDs are references only; the service must not insert or update `APP_USERS`. Seed at least three rows per table, at least five distinct categories, and use valid category/topic foreign keys; author IDs must exist in `APP_USERS` owned by users-service. Test profile uses in-memory H2 and Hibernate create-drop only.
